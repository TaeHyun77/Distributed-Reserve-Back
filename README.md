
### 프로젝트 설명
---
예약, 리워드 지급 등 동시성 이슈가 발생할 수 있는 도메인을 직접 구현하며, 상황에 적합한 동시성 제어 전략을 적용하는 것을 목표로 진행한 프로젝트입니다.

- 예약 생성 로직에 Redisson 기반 분산 락을 적용하여 동일 좌석에 대한 중복 예약을 방지하고, 멱등성 키를 적용하여 네트워크 타임아웃 등으로 동일 요청이 반복되더라도 예약이 한 건만 생성되고 동일한 응답이 반환되도록 하였습니다.

- 예약 취소, 리워드 지급 로직에 DB 비관적 락을 적용하여 크레딧과 리워드의 정합성을 보장하고, 상태 체크를 통해 별도의 멱등성 키 없이 자연 멱등성을 확보하였습니다.<br><br>

### 기술 스택
---
Backend : SpringBoot, Spring Data JPA, Kotlin

Frontend : React, JavaScript

Database/Cache : MySQL, Redis ( Redisson 기반 분산 락 )<br><br>

Etc : SMTP

### 동시성 이슈
---
분산 서버 환경에서는 여러 인스턴스가 동시에 동일한 자원에 접근하거나 변경하면서 동시성 문제가 발생할 수 있습니다. 

비즈니스 로직 내부에 예외 처리를 해두었더라도, 각 서버가 독립적으로 트랜잭션을 수행하면서 모든 요청이 정상 처리되는 것처럼 보이는 현상이 발생할 수 있고, 그 결과 좌석의 중복 예약이나 리워드의 중복 지급 등 데이터 정합성 문제로 이어질 수 있습니다.

이번 프로젝트에서는 리소스의 경합 특성과 보호해야 할 범위에 따라 Redis 분산 락과 DB 비관적 락을 적절히 선택하여 동시성 문제를 해결했습니다.<br><br>

### 기능 구현
---
1. Redisson 분산 락으로 좌석 예약 동시성 제어 및 중복 예약 방지

2. DB 비관적 락으로 리워드 지급 정합성 보장

3. 예약~결제 흐름 전반의 결제 처리 로직 구현

4. SMTP 기반 이메일 발송 기능을 구현하여 사용자 알림 처리

5. k6를 활용해 예약 중복 방지 및 멱등성, 리워드 지급 로직의 동시성 검증 수행

### 트러블 슈팅 및 개선 사항
---
1. 스핀락 기반 분산 락을 Redisson 기반으로 전환하고, leaseTime 설정을 통해 락 관리 방식 개선하였습니다.
   
2. 트랜잭션 커밋 후 락이 해제되도록 하여, 동시성 문제를 해결하고 데이터 정합성을 확보했습니다.
